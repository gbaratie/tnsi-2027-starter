TNSI · TP guidé06 / 15
Atelier · domaine pur

Une valeur métier commence par deux tests.

  1. Prendre une règle du glossaire

    Exemple de secours : une note entière entre 1 et 5. Votre groupe choisit une règle de son domaine.

  2. Écrire le cas valide et le refus

    Créer un test pour chaque borne et une valeur hors borne. Les tests importent directement le domaine.

  3. Implémenter seulement la règle

    Créer un Value Object immuable ; valider à la construction. Ajouter ensuite les entités qui l’utilisent.

À CRÉER · tests/test_domain_rating.py · exemple partiel
import pytest
from filrouge.domain.music import Rating
from filrouge.domain.exceptions import ValidationError

def test_rating_accepts_boundary():
    assert Rating(1).value == 1

def test_rating_rejects_invalid_value():
    with pytest.raises(ValidationError):
        Rating(0)

Vérifier. Les tests fonctionnent sans serveur ni base. Adapter le nom de module et l’exception publique à votre domaine.

Étape 2 · tester les règles07 / 15
Les invariants d’abord

Un test montre ce que le domaine accepte et refuse.

Cas valides

  • construction minimale correcte ;
  • valeurs limites autorisées ;
  • égalité d’un Value Object ;
  • transition métier possible.

Cas invalides

  • identifiant ou libellé vide ;
  • valeur hors borne ;
  • doublon interdit ;
  • transition incohérente.
uv run pytest -k domain

TNSI · TP guidé10 / 15
Atelier · frontière HTTP

Branchez la route après le use case testé.

  1. Créer le port et un fake mémoire

    Dans application/ports/, décrire la capacité. Tester le use case avec trois objets connus.

  2. Créer votre entrée API

    Dans entrypoints/api.py, définir le DTO et une factory create_api(use_case).

  3. Traduire aux deux extrémités

    Lire les paramètres, appeler execute une fois, convertir les résultats en DTO. Le bootstrap compose l’application.

À CRÉER · entrypoints/api.py · squelette incomplet
from fastapi import FastAPI

def create_api(search_tracks):
    app = FastAPI()

    @app.get("/tracks/search")
    def search(mood: str):
        tracks = search_tracks.execute(mood)
        # À faire : DTO et erreurs HTTP.
        return [to_response(t) for t in tracks]

    return app

Vérifier. Le test injecte un use case et appelle la factory. Streamlit réutilise le même cas d’usage, sans appel HTTP imposé.

À vous : un domaine, deux interfaces.

  1. Nommer le métier

    Écrire 8 à 12 termes et deux règles avec exemples valides et invalides.

  2. Modéliser et tester

    2 à 4 entités, 1 à 3 Value Objects ; tests directs des invariants, sans framework.

    Port de capacité + fake mémoire + use case dans application/ ; tester avant l’API.

    Route et DTO dans entrypoints/ ; mêmes paramètres en UI/API, erreur HTTP testée.

À montrer avant de terminer

  • Un invariant accepté puis refusé.
  • Le même use case appelé par UI et API.
  • Une requête invalide et son statut HTTP documenté.
